BEFORE (Verbatim Search):
─────────────────────────────────────────────────────────────────────────────
Statement → Single search query (verbatim) → Results → Scrape → Evidence
            "Deutsche Bank upgraded 3M"

Issues:
  ✗ Generic results
  ✗ Less authoritative sources
  ✗ Single query may miss relevant information
  ✗ Verbatim statements don't match how authoritative sources write


AFTER (Intelligent Query Generation):
─────────────────────────────────────────────────────────────────────────────
Statement → QueryGenerator → Multiple optimized queries → Search each →
"Deutsche Bank       ↓                                      ↓
upgraded 3M"    Extract entities              "Deutsche Bank 3M rating 2025"
                & formulate                   "3M stock upgrade Deutsche Bank"
                targeted queries              "Deutsche Bank analyst ratings"
                                                      ↓
                                              Deduplicate → Scrape → Evidence

Benefits:
  ✓ Domain-aware queries
  ✓ More authoritative sources (financial news, analyst reports)
  ✓ Better coverage with multiple query angles
  ✓ Efficient deduplication prevents redundant scraping
  ✓ Transparent reasoning for debugging/auditing

Deduplication Logic:
─────────────────────────────────────────────────────────────────────────────
seen_urls = set()
for result in search_results:
    if result.link not in seen_urls:
        all_search_results.append(result)
        seen_urls.add(result.link)

This ensures:
  • No URL is scraped multiple times
  • Multiple queries can return overlapping sources
  • Efficient use of API calls
